ChatUI LLM Workbench — 后端接口对接文档

实现以下接口并托管前端静态产物，即可完整驱动这套 UI：LLM Provider 统一配置 / MCP / Skill / 流式对话 · 传输 JSON + SSE · 默认端口 8787（环境变量 PORT 可覆盖）

1. 总体架构

┌─────────────────────────────┐        HTTP / SSE          ┌──────────────────────────────┐
│  前端（静态产物，浏览器）     │  ───────────────────────►  │  你的后端服务                  │
│  - 对话页 / 设置中心          │  GET/POST /api/*          │  - 配置持久化                  │
│  - 会话列表 / 全端 PWA       │  ◄─────────────────────   │  - LLM Provider 适配层         │
│                             │      JSON / SSE 流          │  - MCP 客户端 / 技能执行器      │
└─────────────────────────────┘                            └──────────────────────────────┘
后端职责：① 提供 /api/* 全部接口；② 实现统一 LLM Provider 抽象（配置 → 厂商调用 → SSE 事件流）；③ 实现 Agent 工具循环（function calling）；④ 托管前端静态产物。

2. 前端静态托管约定（全端支持的前提）

路径内容说明

3.1 GET /api/config — 读取配置

设置中心加载时调用，渲染全部 Provider / MCP / Skill 配置。响应为 AppConfig，apiKey 已掩码：

{
  "activeProviderId": "ollama-demo",
  "providers": [{ "id": "ollama-demo", "type": "ollama", "name": "Ollama 本地",
    "baseURL": "http://localhost:11434", "apiKey": "", "model": "ornith-1.5:9b",
    "temperature": 0.7, "maxTokens": 4096, "enabled": true, "models": ["ornith-1.5:9b"] }],
  "mcpServers": [{ "id": "everything", "name": "MCP Everything (stdio 示例)",
    "transport": "stdio", "command": "npx", "args": ["-y", "@modelcontextprotocol/server-everything"],
    "env": {}, "enabled": false }],
  "skills": [{ "id": "get_current_time", "name": "获取当前时间",
    "description": "获取当前日期与时间（含时区）", "type": "builtin", "enabled": true }],
  "systemPrompt": "你是一个通用 AI 助手……",
  "maxToolRounds": 8
}

3.3 POST /api/config/models — 拉取模型列表

POST /api/config/models
{ "type": "ollama", "baseURL": "http://localhost:11434", "apiKey": "", "model": "ornith-1.5:9b" }

→ 200 { "ok": true, "models": ["ornith-1.5:9b", "qwen35-4b:latest"] }

3.10 POST /api/chat — 流式对话（核心，SSE）

POST /api/chat
Content-Type: application/json
{ "messages": [{ "role": "user", "content": "现在几点？" }], "providerId": "ollama-demo", "model": "ornith-1.5:9b" }

响应 Content-Type: text/event-stream; charset=utf-8，事件格式：event: <名>\ndata: <JSON>\n\n。服务端设置 Cache-Control: no-cache, no-transform、X-Accel-Buffering: no、立即 flush；每 15s 发一行 : ping 心跳。

事件data 字段时机
info{ "text" }流程提示（居中显示）
tool_start{ "name", "id", "args" }工具开始执行
tool_result{ "name", "id", "result"?, "error"? }工具执行完成（result/error 二选一）
delta{ "text" }LLM 流式增量文本（逐 token）
done{ "usage"? }正常结束，随后关闭流
error{ "message" }异常终止，随后关闭流
event: info
data: {"text":"已加载 4 个技能（4 个工具）"}

event: tool_start
data: {"name":"get_current_time","id":"call_1","args":"{}"}

event: tool_result
data: {"name":"get_current_time","id":"call_1","result":{"iso":"2026-09-27T14:00:00.000Z","timezone":"Asia/Shanghai"}}

event: delta
data: {"text":"现在是 22:00，今天是 2026 年 9 月 27 日。"}

event: done
data: {"usage":{"eval_count":64}}

4.1 统一 LLM Provider 适配层

方法入参出参说明
chat(req){ model, messages, tools?, temperature?, maxTokens?, onEvent }onEvent 流式回调逐 token 回调 text-delta；识别 tool_calls 回调 tool-call；结束回调 done
test()—{ ok, message }轻量连通性测试
listModels()—string[]拉取模型列表

厂商类型：openai（OpenAI 兼容 /v1/chat/completions 流式）、anthropic（Messages API）、gemini（generateContent 流式）、ollama（/api/chat NDJSON 流式）。新厂商可在「＋ 添加 Provider」预设中扩展。

4.2 工具定义注入

每次对话把启用技能转为 function schema 传入 LLM；建议同时把技能清单以文本追加到系统提示词尾部。启用规则：builtin 启用 → 注入函数；mcp 启用且绑定 server 启用 → 动态注入其全部工具。

{ "type": "function", "function": { "name": "get_current_time", "description": "获取当前日期与时间（含时区）", "parameters": { "type": "object", "properties": {}, "required": [] } } }

4.3 Agent 工具循环

for round in 1..maxToolRounds:
    result = provider.chat(messages, tools)      # 流式输出 delta
    if 无 tool_calls: 结束（emit done）
    messages += assistant(toolCalls)
    for each tool_call:
        emit tool_start
        result = executeSkill(tool_call)          # builtin 函数 或 MCP 调用
        emit tool_result
        messages += tool(toolCallId, JSON(result))
    # 继续下一轮，把工具结果喂回 LLM
上限 maxToolRounds（默认 8）；工具结果截断（如 12KB）防膨胀；客户端断开（req close）时中止厂商请求。
